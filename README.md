# TARA — 16-bit microprogrammed processor (TH1–TH6)

CS2300 · Group G06
Chaithanya PS (CS25B018) · Yash Tulshyan (CS25B095)

TARA is a 16-bit processor built in Logisim-evolution: eight 16-bit registers (R0–R7), a shared
tri-state bus, a 16-bit ALU with accumulator and flags (Z, N, C, V), 64 KiB byte-addressed
little-endian memory, and a microprogrammed control unit (4-bit T-state counter + 2048 × 16 control ROM).
Full design documentation is in `G06_th6_report.pdf` / `.docx`.

## Files

| File | Purpose |
|---|---|
| `G06_th6_tara.circ` | Complete Logisim-evolution circuit. `main` instantiates `taracpu` (the CPU top level). |
| `G06_control_rom.hex` | Control ROM image (Logisim "v2.0 raw", 2048 words × 16 bits). Generated by the script below and already embedded in the `.circ`. |
| `G06_th6_microcode_gen.py` | Generates and verifies the control ROM; can patch it into a `.circ`. |
| `G06_th6_csv_to_hex.sh` | Converts an emulator memory dump (CSV) into a Logisim RAM image. |
| `G06_th6_report.pdf`, `.docx` | Design report (interfaces, ISA, microcode table, design decisions, limitations). |

## Opening the circuit

1. Open `G06_th6_tara.circ` in Logisim-evolution and select the `main` circuit.
2. Pulse the reset input (`RST`) once, then run the clock (Simulate → Ticks Enabled, or Ctrl+T to tick once manually).
3. Observe `PC`, `TSTATE`, `R0`–`R7` and the 32-bit `CYCLES` counter (unsigned decimal). `CYCLES` stops counting when `HLT` freezes the processor.
4. `RST` clears the T-state counter, registers, PC and cycle counter. **It does not clear RAM.**

## Running a program

1. Assemble / emulate your program so that you have its memory image.
   - If your emulator exports a memory dump as CSV, convert it:
     ```
     ./G06_th6_csv_to_hex.sh memory_dump.csv program.hex
     ```
     CSV format: a header row, then `address,hex,decimal` per byte (the decimal column is ignored). Bytes that are
     not listed are 0. The converter does no byte swapping: word *i* is written as the byte at address 2*i*
     followed by the byte at address 2*i*+1, so bytes `34` (addr 0) and `19` (addr 1) become the word `3419`.
     The circuit loads each word exactly as it appears in the hex file.
   - Otherwise write a Logisim "v2.0 raw" file of 16-bit words directly; each word is loaded as written.
2. In Logisim, open `ram_word` (inside `tara_datapath`), right-click the RAM → **Load Image…** → choose `program.hex`.
3. Reset and run. Execution starts at address `0x0000`.
4. Stop when `TSTATE` stays at 3 with the instruction `HLT` fetched; read the results from the register probes.

## Regenerating the control ROM

```
python3 G06_th6_microcode_gen.py                         # writes G06_th6_control_rom.hex
python3 G06_th6_microcode_gen.py in.circ out.circ        # also patches the ROM into a copy of the circuit
```

Before writing anything, the script runs six consistency checks (one bus source per word, every instruction reaches
`STEP_RST` or `HALT`, no simultaneous memory read/write, write enables always have a valid source, branch words depend
only on their own flag, undefined opcodes cannot change state) and the instruction-level invariants in `verify_rom`.
If any check fails, no file is written.

Note: changing the ROM width in Logisim clears its contents; re-run the script with the `in.circ out.circ` form to restore it.

## Architecture summary

- **Registers:** R0–R7 general purpose; **R6 = link register** (written by `CALL`, read by `RET`); **R7 = stack pointer** (stack grows downward, 2 bytes per push).
- **Memory:** 32K × 16-bit words, byte addressed, little-endian. Word accesses ignore address bit 0 (an odd address silently accesses the word at `addr & 0xFFFE`).
- **Control word (16 bits):** `STEP_RST, MAR_LOAD, MDR_LOAD, ACC_LOAD, REG_WE, MEM_READ, MEM_WRITE, STATUS_WE, IMM, IMM_BIT_EXTEND[2], BUS_SOURCE[3], PC_LOAD, HALT`.
  ROM address = `{Z, N, opcode[5], T-state[4]}`.
- **Fetch:** every instruction starts with the same three T-states (T0 `MAR ← PC`, T1 `MDR ← Mem[MAR]; PC ← PC + 2`, T2 `IR ← MDR`).

### Instruction set (opcode in bits 15..11)

| Op | Mnemonic | Format | Operation | Cycles |
|---|---|---|---|---|
| 0 | NOP | F0 | no operation | 4 |
| 1 | HLT | F0 | freeze the T-state counter | 4 |
| 2 | MOV Rd, Rs | F2 | Rd ← Rs | 4 |
| 3 | LIL Rd, imm8 | F3 | Rd ← zext(imm8) | 4 |
| 4 | LIH Rd, imm8 | F3 | Rd ← (imm8 << 8) \| (Rd & 0x00FF) | 7 |
| 5 | LDW Rd, [Rb+off5] | F4 | word load | 7 |
| 6 | STW Rs, [Rb+off5] | F4 | word store | 7 |
| 7 | LDB Rd, [Rb+off5] | F4 | byte load, zero-extended | 7 |
| 8 | STB Rs, [Rb+off5] | F4 | byte store (low byte of Rs only), read-modify-write | 8 |
| 9 | ADD Rd, Ra, Rb | F1 | Rd ← Ra + Rb | 5 |
| 10 | SUB Rd, Ra, Rb | F1 | Rd ← Ra − Rb | 5 |
| 11 | ADDI Rd, imm8 | F3 | Rd ← Rd + sext(imm8) | 5 |
| 12 | (MUL) | — | unimplemented, executes as a 4-cycle NOP | 4 |
| 13–15 | AND / OR / XOR Rd, Ra, Rb | F1 | bitwise | 5 |
| 16 | NOT Rd, Rs | F2 | Rd ← ~Rs | 5 |
| 17, 18 | SHL / SHR Rd, imm | F3 | logical shift by imm8[4:0] | 5 |
| 19 | SLT Rd, Ra, Rb | F1 | Rd ← (Ra < Rb signed) ? 1 : 0 | 5 |
| 20 | BZ Rt, rel8 | F5 | if Rt == 0: PC ← PC + sext(rel8) × 2 | 6 taken / 5 not |
| 21 | BN Rt, rel8 | F5 | if Rt < 0: PC ← PC + sext(rel8) × 2 | 6 taken / 5 not |
| 22 | JMP rel11 | F6 | PC ← PC + sext(rel11) × 2 | 5 |
| 23 | CALL rel11 | F6 | R6 ← PC; PC ← PC + sext(rel11) × 2 | 6 |
| 24 | RET | F0 | PC ← R6 | 4 |
| 25 | PUSH Rs | F7 | R7 ← R7 − 2; Mem16[R7] ← Rs | 9 |
| 26 | POP Rd | F7 | Rd ← Mem16[R7]; R7 ← R7 + 2 | 10 |

Opcodes 27–31 are unassigned and execute as 4-cycle NOPs. Branch/jump offsets are in words (the decoder shifts them left by 1),
relative to the address of the *next* instruction.

### Formats

| Format | Layout (15..0) |
|---|---|
| F0 | `op(5) · 00000000000` |
| F1 | `op(5) · rd(3) · ra(3) · rb(3) · 00` |
| F2 | `op(5) · rd(3) · rs(3) · 00000` |
| F3 | `op(5) · rd(3) · imm8` |
| F4 | `op(5) · rdata(3) · rbase(3) · off5` |
| F5 | `op(5) · rtest(3) · rel8` |

## Example program

`prog2_call_ret_push_pop.hex` (17 words) exercises PUSH, POP, CALL, RET and a nested call. Expected final state
after `HLT`:

| R0 | R1 | R2 | R3 | R4 | R5 | R6 | R7 | PC |
|---|---|---|---|---|---|---|---|---|
| 0x0000 | 0x00AA | 0x00BB | 0x0022 | 0x0011 | 0x0055 | 0x0010 | 0x0080 | 0x0014 |

Memory afterwards: `[0x7C] = 0x0022`, `[0x7E] = 0x0010`. `CYCLES` should read about 104.

## Known limitations

- Unimplemented opcodes (MUL and 27–31) run as NOPs and do not halt the processor.
- Unaligned word accesses are silently aligned (no exception).
- Flags are updated only by BZ/BN (at T3, by testing `Rt & 0xFFFF`); arithmetic instructions do not set them.
- `STB` stores only `Rs[7:0]`. To store a register's upper byte, shift it down into a scratch register first.
- `PUSH`/`POP` change R7 in two steps, so `POP R7` ends with R7 holding the popped word (the incremented SP is overwritten), and `PUSH R7` pushes the original SP.
